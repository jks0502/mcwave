# mcwave：一块会"说话"的桌面墨水屏

> **🎂 Happy Birthday, momosaysay！**
> mcwave 是送给 momosaysay 的生日礼物。屏幕的左半边是 jks，右半边是 momosaysay——每天换一个心情、写一句话，隔着一座城市也能看见彼此。
> 祝你生日快乐，天天开心，每一天都像屏幕上那只水豚一样松弛、可爱。

mcwave 是一台 **4.2 英寸黑白墨水屏桌面摆件**，由一块 ESP32 驱动。它显示南京江宁的天气和下次降雨预报，显示两个人各自的心情和一句话，也能当云相册——所有内容都通过一个网站远程控制，离线时屏幕保持最后一帧。

这个仓库是 mcwave 的**完整收官资料**：固件源码、USB 网关、网站后端、3D 外壳、硬件清单、复刻步骤，以及我从第一块点阵照片相框做到第 **7.1.0** 版固件的全部历程。项目到 2026-11-01 正式结束。

## 它能做什么

| 功能 | 说明 |
| --- | --- |
| 天气页 | 南京江宁区实时温湿度、天气、下一次降雨的时间与概率（数据来自中央气象台、中国天气网，无需 Token）；配一只水豚形象和语录，每次刷新随机换 |
| 双人心情页 | 两个人在网站各选一个心情、写一句话，浏览器把它画成 200×300 的黑白半屏，设备下载后左右拼成整屏（jks 左 / momosaysay 右） |
| 云相册 | 网站上传照片，自动转成 400×300 黑白点阵；可暂停、顺序、随机、自定义间隔；设备本地缓存最多 20 张，断网也能继续轮播 |
| 网站远程控制 | 切页、选图、改间隔；设备主动用 HTTPS 联系网站，不需要端口映射，适配校园网 |
| 离线缓存 | 天气、相册、心情断网后都用最近一次的结果，恢复联网自动更新 |
| 按键 | 短按 BOOT 在天气 / 心情之间切换 |
| 屏幕镜像 | 刷屏成功后把整屏画面回传网站，可以在网页上看到"设备现在显示什么" |
| 无线升级（OTA） | 双应用分区，网站发布固件、设备下载校验、重启确认，失败可回滚；固件带板型标记，防止刷错板 |
| USB 网关 | 插到 Windows 电脑时，由电脑提供时间和网络（固件自己做 HTTPS，电脑只转发加密字节），不用配 Wi-Fi |
| 多网络 | 没插电脑时按优先级连 NJIT（校园网自动认证）> 普通 Wi-Fi |
| 稳定性保护 | 任务看门狗、60 分钟无同步自动重启、欠压硬复位、RTC 看门狗、复位原因计数 |

## 整体架构

```
            ┌──────────────────────────────────────────────┐
  浏览器 ──▶│ Cloudflare Worker + D1 数据库（网站后端）       │
 (jks /     │  · 设备同步接口  · 相册 / 心情 / 固件发布       │
momosaysay) └───────────────▲──────────────────────────────┘
                            │ HTTPS（设备主动联系，TLS 在固件里完成）
          ┌─────────────────┴──────────────────┐
          │              mcwave (ESP32)         │
          │  天气 · 心情 · 相册 · OTA · 屏幕镜像   │
          └───────▲─────────────────────▲───────┘
   Wi-Fi：NJIT(校园网自动认证) > 普通 Wi-Fi      │ USB 串口
                                                │
                                   Windows USB 网关（gateway/）
                                   只转发加密字节，看不到账号密码
```

几个设计选择：

- **设备主动拉取**：设备每隔十几秒 HTTPS 同步一次，网站只记"目标状态"，设备做完回执。这样不需要内网穿透，校园网也能用。
- **固件自己做 TLS**：连 USB 网关也一样——ESP32 自己校验证书，电脑只是个"网线"。
- **全刷后休眠**：HINK 屏不适合局刷，每次全刷后让屏幕休眠，自动刷新最短 60 秒；数据查询和刷屏频率分开配置。
- **失败保留旧内容**：任何网络 / 解析失败都保留上一份有效数据，不把半截响应当成功。

## 复刻步骤

> 详细版（含每一步的检查点）见 [docs/BUILD.md](docs/BUILD.md)。

1. **买硬件**：见上表。先只买驱动板 + 屏幕 + 数据线，就能跑通天气页。
2. **接屏幕**：驱动板断电，拨码 1=B、2=ON，24pin 排线插好（金手指方向对准，扣紧锁扣）。
3. **准备开发环境**：安装 Arduino IDE，装 ESP32 开发板包 3.x。
4. **填密钥**：把 `firmware/` 里的 `*.example.h` 复制成去掉 `.example` 的文件并填写：
   `Secrets.h`（热点）、`NjitSecrets.h` / `CampusSecrets.h`（校园网，可不用）、`MultiNetworkSecrets.h`、`RemoteSecrets.h`（你自己网站的地址和设备令牌）。不用的网络填空串。
5. **准备图片素材**：本仓库**不含**水豚图片与语录字体数据（见[版权说明](#素材与版权说明)）。用 `tools/pack_mcwave_assets.py` 和 `tools/prepare_fonts.py` 生成你自己的 `PackedAssetsData.h`、`NailongSprite.h`，或把天气页的配图换成自己喜欢的。
6. **编译上传**：分区选 `firmware/partitions.csv`，首次通过 USB 用 `tools/flash-mcwave.ps1 -Layout` 写入（会改分区；以后只用不带 `-Layout` 的）。**注意**：脚本里的 MAC 地址是占位符，改成你板子的 MAC；`esptool` 路径、`arduino-cli` 路径也按本机修改。
7. **搭网站后端**（可选，用于心情 / 相册 / 远程控制 / OTA）：把 `site-backend/` 部署到 Cloudflare Worker，建 D1 数据库并执行其中的 `.sql`；设备令牌用 Wrangler 写成 Worker 密钥。全局搜索 `jks0502.xyz`，换成你自己的域名。
8. **（可选）USB 网关**：`gateway/` 里 `python gateway.py --port COMx --console` 调试；`pyinstaller` 打包成 exe 给对方双击安装。

没有网站也能用：只做 1–6 步，设备就是一个"天气桌面摆件"。

## 我是怎么一步步做到现在的

整个项目从 **2026-10-03** 到 **2026-11-01**，一个月，373 次提交。大致分成七个阶段。

### 阶段 0：先让屏幕亮起来（10-03）

第一个"产品 1"其实是个**离线照片相框**：买了微雪 ESP32 驱动板和 4.2 寸屏，把 14 张照片转成 400×300 黑白点阵（每张 15000 字节），每 60 秒翻一张。学会了：拨码开关怎么拨、BUSY 引脚超时怎么保护、1bit 点阵怎么排。这一步的结论是**屏幕和板子是对的**，后面才敢往上堆东西。

### 阶段 1：天气桌面摆件（V1.0–V2.x）

不想只放死图，改成"桌面小钟"：联网取天气，画一个带形象的天气页。从这里开始固件叫 WeatherClock。

### 阶段 2：加赛事页，发现国内网络才是主要难题（V3.x）

加了足球 / NBA / F1 / CS2 赛事页。最早用 Cloudflare Worker 聚合境外接口，结果手机热点下加载失败，V3.1 全改成**国内公开数据源直连**。后面一连串修复都是真实踩出来的：TLS 占满内存、网络读取占满 CPU 触发看门狗、热点不稳定。也是这时加了**断网缓存**和**校园网（SEU-WLAN）网页自动认证**。

### 阶段 3：屏幕适配与降雨预测（V3.7–V3.11）

换成 HINK 屏后发现它不适合局刷，改成**全刷后休眠**，并把"屏幕刷新"和"数据查询"的频率彻底分开。加了"下次降雨时间 + 概率"，并把"今天约 18 时 / 明天约 02 时"这类相对日期算对（跨月、跨年、午夜后）。

### 阶段 4：网站接管（V4.0–V5.x）

写了个人网站，设备主动 HTTPS 联系网站，实现**远程切页**和**私有云相册**（上传自动转点阵、顺序 / 随机轮播、最近 20 张本地缓存）。接着连续做了内存瘦身：固定 1KB 接收缓冲、共用 JSON 工作区、字模二分查找、一次分配生成 JSON，最后把一万句语录砍到一百句，程序瘦了近 600KB。V5.5 改成两个 OTA 分区，**第一次无线升级**成功（下载约 24 分钟）。

### 阶段 5：变成"送给她的礼物"（6.0–6.3，10-21 起）

赛事页对礼物没意义，6.0.0 **去掉赛事页，换成双人心情页**：两个人各选心情写一句话，网站画成黑白半屏，设备拼成整屏。天气页配图改成水豚，心情页换成真正的水豚形象，momosaysay 那半边戴上了帽子。接着做了一整轮**网络性能调优**（超时、保持连接、关 Wi-Fi 省电、失败立即重试），把同步失败率从 6% 压到 0.4%，并加上**屏幕镜像**。

### 阶段 6：把它做成"不会坏"的东西（6.3.1–6.5.1，10-25 起）

礼物不能三天两头卡死。加了任务看门狗、60 分钟无同步自动重启、**欠压硬复位**、RTC 看门狗、复位原因计数；每个保护都做了真实板子上的故障注入测试。然后处理对方那边的网络：接入 NJIT 校园网，DNS 多地址轮转，**NJIT > 普通 Wi-Fi** 优先级，WPA3 兼容，拒绝退避。

### 阶段 7：不依赖 Wi-Fi（7.0.0–7.1.0，10-31 起）

最大的不确定是"她那边的网"。所以做了 **USB 网关**：插上电脑就有时间和网络，固件自己做 TLS，电脑只转发加密字节。串口没有硬件流控、写 Flash 时会丢字节，所以自己做了按字节偏移的确认重传。最后 7.1.0 给固件加了**板型标记**，OTA 时会拒绝错板固件。2026-11-01，mcwave 7.1.0 通过 USB 网关完成最后一次 OTA，项目收官。

## 踩过的坑

- **国内网络 ≠ 境外网络**：境外聚合接口在热点上经常打不开，最后一律国内公开源直连。
- **TLS 很吃内存**：ESP32 一次 TLS 握手就能把堆吃光；固定缓冲、共用工作区、复用连接、传输时关省电，都是为了活下来。
- **ESP32 串口写 Flash 时会丢字节**：USB 网关必须自己做确认重传。
- **HINK 屏不能局刷**：换屏要重新确认刷新方式、初始化和 BUSY 时序，别把一种屏的参数套到另一种。
- **别信"日志成功"**：每一版都要用户亲眼看屏幕，数据成功不等于画面正确。
- **烧录 OTA 分区时**必须同时写 `boot_app0`，不能只写应用区；改分区那次一定先整片备份。
- **电源切换瞬间会让 ESP32 卡死**：所以才有欠压复位和 RTC 看门狗（后来证明实际那次是电池没电了，但保护留着不亏）。

## 已知限制与没验证过的事

诚实记录，别当成"全都验证过了"：

- NJIT / 普通 Wi-Fi 的**实网**稳定性、WPA3 实际关联没有在最终版逐项验到；
- 对方电脑上的 **USB 网关安装与驱动**、电脑休眠恢复没有实测；
- OTA 的**回滚路径**没有实板测过（源码里有 15 分钟 pending-verify 超时）；
- 长达数小时到数天的稳定性只测过 30 分钟～3 小时；
- 充电中拔外部电源会不会让屏幕停刷，最后判定是电池没电，没有再追查。
